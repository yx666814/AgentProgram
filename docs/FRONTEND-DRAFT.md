## 1. 需求和流程

### 1.1 产品目标

前端必须让用户在一个 Windows 本地桌面应用中完成以下闭环：

```text
启动与恢复
-> 创建或打开项目
-> 项目预检
-> Planner
-> Designer
-> Builder
-> Reviewer
-> Deployer
-> 最终交付与审计
```

用户不需要依赖模型文字猜测真实状态。项目、工作流、阶段、任务、Gate、审批、冲突、恢复和交接状态必须由后端 Query、Command 和持久化 Event 驱动。

### 1.2 核心用户流程

#### 首次启动

1. 桌面程序启动后端 Sidecar。
2. 等待 Ready、数据库和迁移检查结果。
3. 没有可恢复项目时进入项目入口。
4. 后端不可用时进入诊断视图，不展示虚假的空项目页。

#### 创建项目

1. 用户填写项目名称和目标。
2. 通过 Electron 原生目录选择能力选择本地工作目录。
3. 选择 Managed Workspace 或 Direct Workspace。
4. 后端创建项目并执行项目预检。
5. 只有后端确认允许启动时，界面才显示开始工作流入口。

#### 五阶段主线

1. 当前阶段解锁后进入对应阶段工作区。
2. 用户发送消息，后端持久化后界面确认发送成功。
3. 当前任务显示流式输出、工具进度、排队消息和取消状态。
4. 正式产出经过 Reviewer A/B、Quality Gate 和审批策略。
5. 后端锁定 ArtifactVersion、创建 Checkpoint 和 HandoffPacket。
6. 收到正式事件后，界面更新阶段完成状态并解锁下游阶段。

#### 审批和能力申请

- MANUAL 的阶段审批支持批准、驳回和要求修改。
- CapabilityRequest 只显示后端允许的决定，不扩大命令、路径、任务和有效期。
- 永久禁止、过期或后端已拒绝的能力不显示批准入口。
- 用户决定只有收到持久化确认事件后才显示成功。

#### 返工和 Warning

- MANUAL 的 WARNING 服从后端审批语义。
- AUTONOMOUS 的 `warning_blocked` 只显示后端允许的 rewrite、open_room 或 abandon。
- `NEEDS_FIX` 的返工目标和失效范围由后端计算。
- `FAIL` 不显示绕过、继续或本地改状态入口。

#### 冲突和恢复

- 外部文件变化必须显示最早受影响阶段和失效范围。
- 文件冲突由后端提供基线、用户版本和 Agent 版本。
- 检查点恢复前必须显示将失效的阶段、产物和交接包。
- Worker、Tool 或应用异常退出后，界面只展示后端允许的继续、停止、放弃或诊断动作。

### 1.3 权限原则

- 五个阶段只显示 RoleCard 和 StageContract 允许的动作。
- Renderer 不直接获得文件系统、Shell、Token 或 SecretStore 能力。
- 所有危险操作必须展示目标、范围、风险、确认和失败恢复。
- 前端本地状态只能保存输入草稿、视图偏好和短暂加载状态。

### 1.4 流程验收

- 首次启动到最终交付主线可以完整走通。
- 每个异常状态都有明确处理路径和返回路径。
- 用户可以区分模型输出、后端状态和正式产物。
- 用户不能通过页面操作绕过阶段锁定、审批、Gate、返工和权限规则。

## 2. 页面结构

### 2.1 全局应用壳

```text
顶部：产品标识 | 当前项目 | 后端连接 | 工作流状态 | 通知 | 设置
左侧：项目 | 当前工作流 | 五阶段 | 产出物 | 事件与审计 | 诊断
主区：当前页面或阶段的主要工作内容
上下文区：阶段、任务、Gate、审批、风险和正式产出摘要
底部：活动任务、排队状态、取消、重试或恢复动作
```

全局应用壳必须在项目切换、阶段切换、断线重连和窗口缩放时保持稳定，不因动态内容改变导航位置。

### 2.2 页面与视图清单

| 编号 | 页面/视图 | 主要职责 |
| --- | --- | --- |
| S00 | 启动与恢复 | 后端 Ready、迁移、遗留任务、恢复和诊断入口 |
| S01 | 项目列表与创建 | 创建、打开项目和选择 Workspace 模式 |
| S02 | 项目预检 | 展示目录、Manifest、命令、冲突和预检证据 |
| S03 | 项目主页 | 工作流总览、阶段进度、待处理事项和最近事件 |
| S04 | 阶段工作区 | 五阶段聊天室、任务、工具、队列和阶段上下文 |
| S05 | 正式产出、Gate 与交接 | 产物版本、证据、Gate、审批和 HandoffPacket |
| S06 | 审批、能力申请与风险 | 阶段审批、CapabilityRequest 和危险操作确认 |
| S07 | 冲突、检查点与恢复 | FileConflict、Checkpoint 和恢复影响范围 |
| S08 | 模型、权限与设置 | ModelProfile、模型槽位、SecretStore 引用和偏好 |
| S09 | 事件、审计与诊断 | Event、ToolCall、Worker、版本、日志和诊断导出 |

### 2.3 导航关系

- 项目入口可以进入项目主页和项目预检。
- 项目主页可以进入当前阶段、产物、冲突、检查点和事件。
- 左侧五阶段入口始终可见，但锁定阶段只能查看锁定原因。
- 阶段工作区可以进入任务、正式产出、Gate、审批和交接详情。
- 全局待处理入口聚合审批、能力申请、冲突、恢复和 Warning。
- 诊断入口在后端不可用、启动失败和正常运行时都可访问。

### 2.4 窗口与层级

- 页面层负责项目和阶段级导航。
- 侧面上下文区负责当前页面的辅助信息，不承载唯一主操作。
- 原生确认对话框用于危险操作、目录选择、恢复和应用退出。
- 非阻断详情使用侧面板或内联展开，不连续堆叠模态框。
- 系统通知只能提示，必须能返回应用内对应记录。

### 2.5 页面结构验收

- S00–S09 都有明确进入条件和离开路径。
- 项目、工作流、阶段、任务、产物、事件和诊断之间可以往返。
- 锁定、只读、暂停、冲突和恢复模式在结构上可区分。
- 待处理事项不遮挡当前任务，不依赖聊天消息提醒。

## 3. 视觉排版

### 3.1 草案阶段目标

视觉排版只验证阅读顺序、密度、对齐、分组和层级，不冻结最终品牌视觉。

### 3.2 信息优先级

1. 当前项目、工作流和阶段状态。
2. 当前用户必须处理的审批、冲突、恢复或错误。
3. 当前任务、工具、队列和正式产出进度。
4. 聊天内容、模型流式输出和辅助解释。
5. 历史事件、用量、版本和诊断细节。

### 3.3 排版规则

- 标题表达当前对象，不使用营销式口号。
- 页面内主要标题、分区标题、字段标签和说明文本形成稳定层级。
- 状态词必须同时依赖文字，不只依赖颜色或图标。
- 表格、时间线和列表优先用于高密度审计信息。
- 长消息、日志、差异和错误证据使用可滚动区域，不撑开整个窗口。
- 关键路径、Hash、错误代码和命令使用等宽排版并支持复制。
- 主操作位置稳定；危险操作与普通操作保持距离。

### 3.4 布局密度

- 项目主页以扫描和快速恢复工作为目标。
- 阶段工作区以聊天、任务和阶段上下文并行阅读为目标。
- 审批和冲突视图以证据比较和影响范围为目标。
- 诊断与审计视图以筛选、检索和追踪为目标。

### 3.5 视觉排版验收

- 不查看颜色时仍能理解页面层级和状态。
- 主要操作、危险操作和只读信息不会混淆。
- 1280×720 的常用最小工作窗口内仍可完成核心流程。
- 长路径、长模型名、长错误和中文/英文混排不会遮挡相邻内容。

## 4. 组件规范

### 4.1 组件分层

#### 应用级组件

- 应用壳、项目切换、阶段导航、连接状态、通知中心和诊断入口。

#### 领域级组件

- Workflow 状态、StageRun 状态、任务队列、消息流、ArtifactVersion、Quality Gate、Approval、CapabilityRequest、HandoffPacket、ChangeRequest、Checkpoint 和 FileConflict。

#### 基础交互组件

- 按钮、输入、选择器、标签、状态标记、表格、树、时间线、对话框、侧面板、菜单、分页、加载和错误提示。

### 4.2 组件必备状态

每个可交互组件必须定义：

- 默认、悬停、聚焦、按下和禁用。
- 加载、提交中、成功确认和失败。
- 权限不足、后端不可用、对象过期和版本冲突。
- 键盘操作、焦点顺序和屏幕阅读器名称。

### 4.3 领域组件要求

- Workflow/Stage 状态组件只接受后端枚举，不接受任意字符串。
- 消息组件区分持久化消息、临时模型流、系统事件、工具结果和正式产物通知。
- Approval 与 CapabilityRequest 不能共用不受约束的通用决定按钮。
- Gate 组件必须展示结果、证据、阻断规则和后端允许动作。
- HandoffPacket 只读，不提供创建和编辑组件。
- FileConflict 必须同时展示基线、用户版本、Agent 版本和影响范围。

### 4.4 组件接口规则

- 业务组件输入使用阶段 5 冻结的类型化 Schema。
- 组件触发 Application Command，不直接修改领域状态。
- 命令结果通过响应和持久化事件更新读模型。
- 组件内不得拼接未注册接口路径或发明事件类型。

### 4.5 组件规范验收

- 每个业务组件有明确依赖、输入、输出和权限。
- 同一领域状态在所有页面使用一致组件和文字。
- 禁用状态说明真实原因，不只降低透明度。
- 组件可以独立覆盖正常、异常和恢复状态测试。

## 5. 交互状态

### 5.1 命令生命周期

```text
可操作
-> 用户确认
-> 提交中
-> 后端接受或拒绝
-> 等待持久化事件
-> 更新界面读模型
```

前端不能在请求发出时提前显示完成。超时、断线或事件延迟时，界面必须保留关联 ID 并允许重新查询。

### 5.2 通用页面状态

- `loading`：首次加载或重新拉取。
- `empty`：后端成功返回空集合。
- `error`：请求失败并包含真实错误代码。
- `forbidden`：权限或阶段规则拒绝。
- `unavailable`：后端、Worker、模型或 SecretStore 不可用。
- `stale`：事件断线或版本落后，需要重新同步。
- `conflict`：版本、文件或状态冲突。
- `expired`：审批、能力申请或任务已经过期。

### 5.3 工作流状态呈现

- `created`：可预检或开始。
- `running`：显示当前阶段和活动任务。
- `waiting_user`：突出待处理事项和影响范围。
- `warning_blocked`：只显示后端允许动作。
- `paused`：显示继续条件和未完成任务状态。
- `external_conflict`：阻断写入并进入冲突处理。
- `interrupted`：显示恢复证据和后端允许的恢复命令。
- `failed`：显示失败原因、证据和后续允许路径。
- `stopped`、`abandoned`、`completed`：明确只读范围和可重新进入方式。

### 5.4 消息和任务状态

- 用户消息只有收到 `message.created` 后才显示为已发送。
- `model.delta` 是临时流，不进入正式历史。
- 活动任务期间的新消息显示排队位置和取消排队入口。
- 任务取消后等待 `task.cancelled` 或 `task.interrupted`。
- 已完成阶段默认只读，咨询与 reopen 使用不同入口和说明。

### 5.5 危险操作状态

- 停止、放弃、恢复检查点、解决冲突和关闭应用必须展示后果。
- 影响文件、阶段、产物和交接包的操作必须展示失效范围。
- 用户取消确认时不产生业务命令。
- 命令失败时保留输入、错误证据和可执行恢复动作。

### 5.6 交互状态验收

- 每个成功状态都有后端响应或持久化事件证据。
- 每个错误状态都有错误代码、说明和下一步。
- 断线重连不会重复消息、重复决定或丢失排队状态。
- 无后端实现的功能不会显示为可点击控件。

## 6. 多端适配

### 6.1 V1 适配范围

V1 的“多端”限定为 Windows 桌面窗口、显示器和缩放环境，不包含手机、平板、浏览器 Web 版或云端控制台。

### 6.2 窗口尺寸

- 常用最小工作窗口：1280×720。
- 标准工作窗口：1440×900。
- 宽屏和高分辨率窗口：保持内容最大阅读宽度，额外空间用于上下文和审计信息。
- 窄窗口优先收起次要上下文区，不隐藏主操作和待处理状态。

### 6.3 Windows 缩放与显示器

- 支持 Windows 100%、125%、150%、175% 和 200% 缩放验证。
- 支持主副显示器 DPI 不同情况下移动窗口。
- 不使用依赖固定物理像素的文本和点击区域。
- 窗口记忆位置前校验显示器仍存在，避免恢复到屏幕外。

### 6.4 输入方式

- 鼠标和键盘均可完成核心流程。
- 支持可发现的快捷键，但快捷键不能成为唯一入口。
- 焦点顺序服从视觉顺序，模态框必须锁定并正确恢复焦点。
- 长任务、审批和错误可使用 Windows 系统通知，但通知不承载完整操作。

### 6.5 可访问性

- 状态不只使用颜色表达。
- 文本缩放后不遮挡、不截断关键操作。
- 表单具有标签、说明、错误关联和键盘提交规则。
- 动效遵循系统减少动态效果偏好。
- 高对比模式下保持边界、焦点和状态可识别。

### 6.6 多端适配验收

- 规定窗口尺寸和缩放组合完成截图与交互检查。
- 键盘可以完成创建项目、阶段操作、审批、冲突和设置流程。
- 跨显示器、最小化、恢复和重启不会丢失窗口或业务状态。
- 不为 V1 设计不可交付的移动端或 Web 端交互。

## 7. 开发验收

### 7.1 草案验收门禁

- S00–S09 页面结构完整。
- 首次启动到最终交付主线可走通。
- 所有后端状态、错误和权限都有前端呈现。
- 审批、冲突、恢复、设置和诊断具备异常路径。
- 页面和组件没有无后端能力的可点击交互。
- 用户确认后才创建草案母版文件。

### 7.2 草案母版验收门禁

- 页面、路由、导航和窗口层级冻结。
- 组件状态、交互状态和文字规则冻结。
- API、Application Command、Event、Permission 和错误映射完整。
- 键盘、可访问性、窗口尺寸和 Windows 缩放规则冻结。
- 所有设计变更通过版本化 Change Request 评审。

### 7.3 正式开发前端母版验收门禁

- Electron Renderer/Preload 工程边界建立。
- 设计令牌、基础组件、应用壳和路由建立。
- 类型化 API Client 和事件状态层只使用冻结契约。
- 基础组件覆盖正常、加载、空、错误、权限和恢复状态。
- 母版代码不包含业务假数据驱动的成功路径。

### 7.4 正式前端验收门禁

- S00–S09 全部页面和状态实现。
- 所有业务动作真实调用后端并等待确认事件。
- REST、WebSocket、认证、分页、幂等、错误和恢复行为通过契约测试。
- Manual、Autonomous、Warning、返工、审批、CapabilityRequest、冲突和恢复完成端到端验证。
- Windows 常用尺寸、DPI、键盘、可访问性和窗口生命周期通过验收。
- 无死控件、无假弹窗、无 Mock 成功、无未批准接口。

### 7.5 前后端功能矩阵要求

每一项可用交互必须在草案母版和开发验收中记录：

```text
页面/组件
-> UI 控件或导航
-> Query / Application Command
-> 请求参数与权限
-> 成功响应或持久化 Event
-> 前端状态更新
-> 错误、取消、重试与恢复
-> 自动化测试
```

### 7.6 验收证据

后续版本需要附带以下证据：

- 页面与状态清单。
- 前后端功能矩阵。
- 组件和可访问性检查结果。
- 常用窗口尺寸与 DPI 截图。
