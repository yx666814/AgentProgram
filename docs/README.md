# 契约化多 Agent 软件交付编排平台——文档总览

本文档库用于在编码前固定项目目标、产品边界、工作流规则和验收标准。后端实现必须以已批准文档为依据；如果实现需要改变已批准规则，应先更新文档并记录决策。

## 文档语言

- 说明、规则、需求和验收标准使用中文。
- 类名、字段名、状态名、API、事件名和代码标识符使用英文。
- 重要术语首次出现时使用“中文名称（English Name）”。
- 协议中的枚举值必须使用固定英文，不在实现中使用同义词替换。

## 规范性用语

- “必须”：实现不可违反的要求。
- “应当”：默认需要满足，只有记录架构决策后才能偏离。
- “可以”：可选能力，不构成当前版本的交付条件。

## 文档批准流程

1. 讨论一个边界明确的主题。
2. 给出可比较的设计方案。
3. 用户确认采用的方案。
4. 将确认内容写入对应文档。
5. 检查占位内容、内部矛盾、歧义和范围膨胀。
6. 用户审阅文档。
7. 文档批准后才能进入实现计划。
